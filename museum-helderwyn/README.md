# Helderwyn Museum of Making: a museum website

The website for Helderwyn Museum of Making (fictional), a craft and tools museum in an invented river town, built on Raytha. The home page is an accession wall of featured objects with museum wall labels, followed by a floor plan of galleries, current exhibitions, programs and journal. Object pages carry accession numbers, materials and credit lines; exhibition pages carry wall text; and members-only pages for patrons and staff are gated on the server. "Accession wall" design — no payment, registration, upload, sign-up or contact forms. The kit suits an agency or freelancer building sites for museums, historic houses and craft collections.

## Rebuild

```bash
RAYTHA_URL=https://your-site.example RAYTHA_API_KEY=... bash build.sh
```

7 content types (exhibitions, objects, galleries, events, people, journal, packets), 2 user groups (`members`, `staff`), site pages (home, about, visit, membership, members room, staff room, search), menus. Server-rendered Liquid only. `build.sh` generates the object plates, posters, gallery plans and portraits if `seed/art` is missing, runs `../scripts/build-example.sh`, then runs the route check.

## How the pages work

- Each object stores an `accession` number, maker, date, materials, credit line, gallery code and on-view status. Templates render a wall label from those fields.
- Galleries store plan coordinates (`plan_x`, `plan_y`, `plan_w`, `plan_h`) and a color; the floor plan places each room as an absolutely positioned link.
- Exhibitions store a pipe-separated list of featured accession numbers; the detail template loads objects and matches on `accession`.
- Programs and packets have an `audience` field (`public`, `members`, `staff`). Templates read `CurrentUser.UserGroups` on the server.
- Search runs `get_content_items` with an OData `contains(...)` filter across seven content types.

## Members-only areas

- Packets and some programs have an `audience` field (`public`, `members`, `staff`).
- Templates read `CurrentUser.UserGroups` on the server and render either the content or a lock panel with a sign-in link. Staff see everything members see; admins see everything.
- `/members` (template `hm_members`) shows a member card, member programs and packets, only for the `members` group.
- `/staff-room` (template `hm_staff`) shows desk coverage, staff programs, loan checklists and gallery notes, only for the `staff` group.
- To try it, create a public user in the admin, add them to `members` and/or `staff`, and sign in at `/account/login`. There is no registration form on purpose.

## Notes

- Object plates, exhibition posters, gallery plans, portraits and journal art (`seed/art/*.svg`) are generated by `seed/make-art.py`; `build.sh` runs it when the folder is missing. No real object, building or person is pictured.
- Dropdown values are rendered as their developer names and mapped to labels in the templates with `case`.
- Field values are captured into strings before they are compared.
- Everything is fictional: the museum, town, people, objects and figures. Phone numbers use the 555 range.
